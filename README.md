# 叫号条（Callslip）

银行网点柜面叫号：取号入队 → 叫号推进 → 过号回收/重叫 → 当日队列封口。

- 前端 http://127.0.0.1:6400
- API http://127.0.0.1:11400
- `docker compose up -d --build`

## 过号回收：作废 vs 重叫（架构口径）

全局唯一贯彻「**作废为准**」，不与其他口径混用：

- 号牌一旦进入 `已作废` 即终态：重叫**整笔拒绝**（不写重叫事件、不占窗、不动窗口指针）。
- 重叫命中即落 `办理中` 并占窗；此后再作废按状态规则**硬拒**（已重叫不得再被作废）。
- 作废与重叫都只落在回收页射程（`等候` / `过号`）；`办理中` / `叫号中` / `已办结` 不在作废范围。

### 一致性与可重放

- 每个写请求 = 一个 `BEGIN IMMEDIATE` 事务：读状态 → 判定 → 改号牌 → 改窗口当前号指针 →
  写 `call_events` 整段串行。并发双点（作废+重叫）只有一个赢家，绝不会出现
  「已作废又办理」或双终态；任一步失败整笔回滚，不留半截。
- 库层面再加部分唯一索引 `uq_tickets_active_window`：同一窗口至多一张 `叫号中/办理中` 号牌。
- `call_events` 记录 `from_status` / `to_status`；`GET /api/号牌/{id}/回放` 按事件序重放并核链，
  回收页可从叫号流水一键回放，验证双动作结局未分裂。

### 接口

| 动作 | 接口 | 成功 | 冲突 |
|---|---|---|---|
| 作废 | `POST /api/号牌/{id}/作废` | 200 `已作废`，不占窗 | 已作废/已办结/办理中 → 409 |
| 重叫 | `POST /api/号牌/{id}/重叫` | 200 `办理中`，占窗 | 已作废/已办结/窗口在他办 → 409 |
| 回放 | `GET /api/号牌/{id}/回放` | 事件链 + 闭合判定 | — |

回执（作废/重叫响应）同时带出：号牌终态、`窗口指针`、`占窗`、本次 `事件`，供回收页、
等候墙、叫号流水、总览两桶同刷。

